# Q5 持久化记忆与角色日记

2026-10-30，插件 0.10.0。实现位于自包含的插件文件
`memory_repository.py`、`persistent_memory.py`、`diary_jobs.py`，随
`configure.py` 的插件清单部署；没有另起 Agent 或第二份完整聊天历史。

## 已定规则

- 普通偏好、重要事件和敏感事实自动提取，不另行询问同意。只从明确的消息证据提取，置信度低于 0.65 不进入可回忆记录。
- 事实和修改前版本无限期保存，不按时间淘汰。用户纠正同一属性时更新活动版本，旧版本保留于 `memory_revisions`，不继续当作当前事实召回。
- 原始摘要绑定角色、机器人 QQ 和所属私聊/群；群成员事实另带发言者身份。同名昵称不能改变归属。当前不实现“忘记某人”、清除或 QQ 记忆管理工具。
- 跨会话只开放已处理的角色话题体验。模型只选普通话题分类，代码从 `memory_shared_topics` 选择固定泛化文本；私人摘要、昵称、QQ 号、来源消息和具体偏好不会复制到共享区。敏感事实不产生共享投影。

## 写入、检索和模型请求

通过入站去重/权限检查的文字消息和成功 ASR 转写自动进入 SQLite 持久处理队列；普通被动群消息可以记录，已禁用/静默群不记录。系统事件、自身消息和管理诊断不作为学习素材。队列使用原消息 ID 幂等，故障重试预算与租约落库，成功提取后清空队列原文，只留下摘要和来源元数据。

后台使用现有本地 Provider、`MediaClient.admission()` 和项目 GPU 调度。没有新模型进程，没有工具执行器，所有整理、压缩、日记请求都显式禁用工具。失败或取消保留待处理源，指数退避最长一小时；停机取消本插件任务并释放准入租约。

`memory_items` 保存事实；`memory_fts` 由插入/更新/删除触发器同步。中文构建双字检索词，英文按词检索，用户文本不直接作为 FTS 表达式。SQL 先建立授权集合，再查询 FTS；只取当前 owner 或同机器人/角色的共享投影。按关键词命中、重要性×置信度和更新时间排序，候选最多 64 条，视频最多 3 条。FTS 是词法检索，不承诺任意同义表达都能命中；无命中时补充高重要性近期记录。

每次主 Agent 请求在最后一条真实用户 JSON 中临时增加 `relevant_memories`，附来源、时间、置信度和共享标记；主动补发同样可以召回。固定的 `memory_use` 规则单独说明资料的含义。消息采用复制后注入，保存 AstrBot 历史前恢复原消息，不把重复召回资料累积成新聊天。整个记忆流程不修改人格文件或模型权重。

记忆上限为模型上下文的 25%，并受“上下文减去输出、余量、系统规则、工具 schema 和当前完整轮次”进一步约束。当前 32768 上下文最多分配 8192 token；主请求继续预留 1536 输出和 256 余量。使用本机 `/apply-template`、`/tokenize` 计算实际输入；全部请求仍由 `RequestBudget.fit` 做最终整轮裁剪。

召回结果超预算时进行一次逻辑压缩；压缩器输入自身超窗则分成有界子批次。结果按 owner、角色、源记录版本和预算缓存，并保存来源关系；相同输入直接复用，事实修订自动改变缓存键。原始记录无限期保留。压缩失败、输出不合法或预算不足时只保留可容纳的完整高优先级记录，不截断 JSON、不编造摘要。压缩请求计入当前 Agent 的请求/时长预算，并为主回答预留一次请求。

## 日记与公开候选

插件初始化启动 APScheduler，默认本机 IANA 时区的 23:30，启动日志记录解析后的时区；可配置 `memory_timezone=Asia/Hong_Kong`。每天也有一分钟恢复扫描，按已识别机器人和角色补写首次记录以来错过的日期，每次每账号最多处理七个日期。

日记日期 D 覆盖 D−1 的 23:30 至 D 的 23:30，截止后半小时计入次日，避免末段消息丢失。当天无素材也写平静的角色感受，不编造交流。尚未提取的截止前消息会延后写作，避免把未整理材料当作当天没有发生。

每次最多选八条高置信素材，生成 200～400 字私人日记，标记 `[私人]`。原文和私人元记忆归角色私密区，任何普通 QQ 会话都不能检索整篇混合来源日记。按 `(bot, character, entry_date)` 唯一事务提交，重试、重启和多实例不能增加第二篇。

有可共享话题时，另发一次只含泛化资料的请求生成 200～400 字公开候选，不传私人草稿、原始摘要、身份或来源消息。候选通过格式及标识检查后，单独成为共享日记记忆。`diary_public_candidates` 视图提供 `privacy_level=public_candidate` 的候选给未来 Q6；私人正文不在该视图。Q5 不启用 QQ 空间或任何自动发布。

## 配置与本地操作

插件 `_conf_schema.json` 提供 `memory_enabled=true`、`diary_enabled=true`、`diary_time=23:30`、`memory_timezone=system`。修改插件配置后正常重启生效。`memory_enabled=false` 停止提取、召回与日记，数据库不删除；`diary_enabled=false` 只停日记。提示词仍从 `configs/qq_companion/prompts.yaml` 每次读取。

正式数据为 `storage/qq_companion/memories.sqlite3`，或随 `ASTRBOT_CHAT_STATE_DIR` 指定目录。运行中的备份应使用 SQLite backup API；停止服务后可复制数据库。原始敏感摘要、私密日记和完整模型调试日志都属于本机私密数据，不能公开提交。

仅本机管理员 CLI 可查看：

```powershell
envs/astrbot/Scripts/python.exe scripts/qq_companion/memory.py status
envs/astrbot/Scripts/python.exe scripts/qq_companion/memory.py search --owner qq:999:dm:101 音乐
envs/astrbot/Scripts/python.exe scripts/qq_companion/memory.py diary --bot 999 --date 2026-10-30
```

命令中的 QQ ID 为合成示例，应替换为实际身份。CLI 没有删除或“忘记某人”入口。Q7/Q8 可通过受信任代码调用 `MemoryRepository.add_video(owner, source_ref, summary, tags, ...)` 接入；该数据始终保留 `source_type=douyin`，不成为用户个人事实。
