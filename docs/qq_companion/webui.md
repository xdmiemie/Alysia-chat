# 大肥鱼控制台

在文件资源管理器中双击根目录的 **`启动astrbot-chat.cmd`** 即可启动模型、语音、QQ 和抖音模块；所有服务就绪后自动用 Edge（未安装时使用 Chrome）打开独立 WebUI 窗口。重复双击会复用已有服务并打开另一个窗口，首次加载模型可能需要几分钟。仍需保持 NTQQ 登录；独立窗口使用项目专用的浏览器配置，首次需要登录 AstrBot，之后保留该窗口的登录状态。

启动成功后进度终端自动关闭。**关闭最后一个独立 WebUI 窗口，约两秒后开始停止整个项目，包括模型、语音、AstrBot、SnowLuma 和抖音服务，并释放所占显存。** 刷新、切换页面或最小化不会停止服务；日常浏览器窗口及 NTQQ 不受影响。在普通浏览器中手动访问网页不参与退出判断。升级前已运行的旧监督器会在下次双击时自动重启，以接入窗口管理。

也可在 PowerShell 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/qq_companion/stop_all.ps1`。直接运行 `start_all.ps1` 仍按终端方式管理，通过 Ctrl+C 或停止脚本退出；之后若双击打开独立 WebUI，也会启用关闭窗口退出。启动失败会保留进度终端显示提示，并清理本次启动的服务。日志位于 `storage/qq_companion/logs/launcher.log` 和同目录下各服务日志。

启动项目后，登录 [AstrBot WebUI](http://127.0.0.1:6185)，点击左侧扩展功能里的「大肥鱼控制台」。也可以通过「插件 → 大肥鱼控制台 → View」进入。直达地址：`http://127.0.0.1:6185/#/plugin-view/astrbot_chat_q1/console`。

页面由插件 `views/console` 提供，沿用 AstrBot 的登录鉴权和插件页面桥接，不增加公网服务或另一套密码。`configure.py --apply` 和正常启动都会部署 Python 模块、页面及中文名称。

## 功能与生效方式

| 栏目 | 功能 | 保存后的行为 |
| --- | --- | --- |
| 抖音视频监控 | 搜索、分页查看视频原链接、内容摘要、评价依据、不确定项、分享意图和实际发送记录 | 读取实际 Worker 数据；未评价不等于无分享意图；新记录包含冷却、每日上限等跳过原因 |
| 记忆库 | 长期记忆、私人日记的增删查改，显示所属会话、来源、时间、标签、置信度与重要性 | 更新真实记忆库和全文索引，清除旧压缩缓存；撤回受影响的共享派生记录。编辑日志留在本地 |
| 上下文控制 | 会话列表、逐条消息增删改、清空上下文、创建私聊上下文；查看模型调用记录 | 修改下一次请求实际使用的 AstrBot 会话或群临时窗口。QQ 忙时拒绝编辑，旧页面不能覆盖新内容 |
| 模型参数 | 上下文容量、GPU 层数、缓存、视觉 token、输出/思考预算、温度、Top P/K、分阶段思考 | 等待在途任务结束后，由现有监督器保存并只重启 Qwen；健康与推理检查失败则恢复旧配置。显示任务进度和失败原因 |
| 人物性格 | 编辑当前角色的 AstrBot 人格 | QQ、日记和抖音从同一人格来源读取；下一次请求生效，启动不再用文件覆盖 WebUI 修改 |
| 流量监控 | 输入、输出、缓存命中 token，按调用阶段及 UTC 日期汇总 | 统计原始模型 `usage`，按请求 UUID 去重、跨日志轮转持久保存；取消或失败且未报告用量的请求单独计数 |
| 应用设置 | QQ 会话白名单、抖音分享好友名单的增删查改与启停，后台活动/休息时段、每小时刷视频数、分享开关/上限/冷却、空闲恢复时间、追加回复次数、群自动接话、日记时间与上下文预算 | QQ 名单立即刷新所选原生配置的访问规则，抖音好友名单由 Worker 热读；其他应用参数更新运行对象和持久配置。休息只停止后台刷视频，QQ 仍然响应；主回复后的追加上限可设 0–5 |
| 系统提示词 | 每项显示中文名、括号中的 YAML 原名、调用时机，支持单项编辑，包括模型协议覆盖项 | 原子保存 `prompts.yaml`，保留注释和其他段落，校验必需键及变量占位符；下一次调用读取 |

上下文中的 **request 是当次输入，response 是模型回复**。调用记录只显示最后一次用户输入及其工具轮次，不重复展示前面的历史上下文，也不返回工具定义或系统提示词正文；系统提示词只列 `prompts.yaml` 名称。模型思考内容不展示。实际会话编辑列表每条消息仅出现一次；工具调用及结果必须保持成对，删除其中一项会一并删除关联调用/结果，历史调用不会重新执行。

私聊新增会话使用 `qq:机器人QQ:dm:好友QQ`。新增记忆可使用同样的私聊/群归属，或 `qq:机器人QQ:shared:elysia` 作为该机器人当前角色的共享记忆。已有记忆编辑不迁移归属。清空会话不删除长期记忆；删除私人日记不会删除已经发布的 QQ 空间动态。

应用设置顶部的「QQ 会话白名单」控制哪些私聊和群聊可以使用机器人。选择配置文件后可搜索会话、按 QQ 号或群号新增、修改及删除，也支持粘贴 `/sid` 获得的完整会话 ID。私聊和群聊分别添加；每项操作独立保存，不会顺带修改后台作息或抖音参数。沿用 AstrBot 原生语义：开关关闭或名单为空时不限制会话，既有管理员豁免在面板中显示。保存后立即更新对应配置的消息流水线；旧页面冲突会拒绝写入，更新流水线失败则回滚保存内容。

下方的「抖音分享好友白名单」独立控制视频自动分享收件人，最多20位。可按昵称或抖音号搜索、新增、修改昵称/抖音号、启用或停用分享权限及删除。完整抖音号和与主页一致的昵称均为必填；重复抖音号、当前分享账号自身、空昵称及超额名单会拒绝保存。空名单不会向任何好友分享。保存直接更新 `douyin.local.json` 的 `friends`，Worker 无需重启；实际发送前仍核验身份、互关、配额与冷却。页面分别保存两类名单，保留其他尚未保存的应用参数；名单和账号变化会使旧版本保存失效，防止覆盖新配置。

原生 AstrBot 人格设置对同一人格的修改仍然有效。`system_prompt.txt` 只负责首次初始化人物；现有人格及开场对话由 AstrBot 数据库保存。原生流量统计确实记录主 Agent 的用量，但不覆盖所有后台任务；控制台增加统一的逐请求统计。上线前的数据只能回填仍保留在本地模型日志里的记录，不把它当成全部历史用量。

模型参数只在监督器运行时允许提交重启。队列、重启中、完成、回滚和失败均有状态记录；监督器中途退出会从该任务的备份恢复配置。采样参数修改保留视觉能力验证；上下文容量、GPU/缓存或视觉 token 等结构性参数改变后，视觉门禁需要重新验证，页面会显示状态。相关验证命令：

```powershell
envs/astrbot/Scripts/python.exe scripts/qq_companion/probe_q7_model.py --use-running --enable-passed --output storage/temporary/q7-settings-check
```

应用设置新增三组私聊主动回复配置：

- **对话内主动回复**：主回复照常发送；模型生成有效、非空且不重复的追加意愿后，才抽取一次概率并计入保底。默认长期平均命中率 30%，连续第 5 次必定命中，命中后重新计数；每个私聊独立保存，重启不清零。平均概率低于 `1/保底次数` 时自动纠正，例如五次保底的 10% 保存为 20%。设置为 20% 时前四次为 0，第五次为 100%；界面显示当前逐次概率。
- **聊天内容计划**：默认启用，仅私聊，没有额外冷却，每个私聊默认最多 5 个待执行计划。满额跳过新计划，已有计划可按后续聊天更新或取消。用户说睡了时可安排八小时后关心，有明确时间则优先遵循；到期再结合最新上下文和时间决定说什么。已有历史不会在首次升级时补建聊天计划。
- **固定轮次主动回复**：默认启用，已有私聊每轮独立随机 `120±20` 分钟，即 100～140 分钟。到期判断，有话才说，没有则跳过至下一轮；不另加冷却。基础间隔、前后波动均可修改，波动过大时自动纠正，保证最短间隔至少一分钟。更改周期参数或重新启用时，从保存时间重新排下一轮；正常重启保留原时间，离线错过多轮只处理一轮。

两个计划开关独立于对话内概率。关闭聊天计划开关会暂停待执行计划；关闭期间的消息不补建新计划。QQ 正在回复时让前台优先，新消息会取消尚未发送的旧判断。发送前重新验证当前白名单、会话启用状态及机器人账号。计划、抽取次数和发送状态保存在 `storage/qq_companion/proactive.sqlite3`；已提交但未确认的发送不会自动重发，确认送达才写入会话历史。

`proactive_plan` 只规划用户真实事项的未来进展，普通闲聊不能借延时计划绕过即时追加概率。未提供时长时可估计；已经开始但没有时长线索的日常事项，提示词默认半小时后首次关心，睡眠另按八小时。时间统一优先填写带时区的绝对时刻。同轮动作冲突时取消优先，不能取消后又重建同一事项。

到期先用 `proactive_review` 提取事件是否存在、是否已经结束以及是否禁止联系，程序依据这些事实决定是否继续；固定轮次另外判断有无自然话题。审核不注入人设，也不以旧计划的理由替代真实对话证据；单独标出最后一条用户消息，防止早期状态覆盖后续完成或取消。通过后才用 `proactive_reply` 生成措辞，人设作为输入资料。生成阶段接收审核后的目的、当前时间与近期主动消息，不把旧用户末句再当成新请求。规划使用 provider 已启用的推理能力，输出/推理预算为 2048/1024；状态提取与措辞各为 512，采用非推理模式。都走后台优先级并可被 QQ 前台中断。三项提示词均可在系统提示词页面编辑，具体场景只放在验证脚本里。

新机制验证：`envs/astrbot/Scripts/python.exe -m pytest tests/test_qq_proactive.py tests/test_qq_agent.py tests/test_qq_web_control.py -q`。`probe_proactive.py` 验证八小时计划与到期表达；`probe_proactive_prompts.py` 使用当前模型、provider 配置与人设验证未写进提示词的正样本、普通问答、完成/取消、旧误建计划与免打扰。两者只使用隔离的合成会话，禁止调用 QQ 发送接口；后者报告位于 `storage/temporary/proactive-prompt-fix/report.json`，调试记录也隔离保存。

## 接口与验证

所有接口属于 AstrBot 登录保护下的 `/api/v1/plugins/extensions/astrbot_chat_q1/control/`：`overview`、`videos`、`memory`、`contexts`、`exchanges`、`model`、`persona`、`usage`、`settings`、`whitelist`、`douyin-whitelist`、`prompts`。读取使用 GET，操作使用 POST；写入携带读取时返回的 `revision`，防止并发覆盖。`whitelist` 支持按 `profile` 选配置及 `create/update/delete/configure` 操作；`douyin-whitelist` 支持 `create/update/delete`，`values` 包含 `douyin_id/name/opted_in`，启停通过 `update` 修改 `opted_in`。凭据不传到插件 iframe。

```powershell
envs/astrbot/Scripts/python.exe -m pytest tests/test_qq_web_control.py -q
envs/astrbot/Scripts/python.exe scripts/qq_companion/probe_web_control.py
envs/astrbot/Scripts/python.exe scripts/qq_companion/probe_model_control.py
```

WebUI 验证使用独立 AstrBot 实例、真实登录和真实浏览器，检查 8 个页面、接口鉴权、记忆/上下文/人格/配置/提示词的保存，以及窄屏布局。模型验证运行实际 Qwen，连续修改、重启、恢复原参数。测试不连接 QQ 或抖音，不向好友发送消息。测试结束关闭其拥有的进程；报告和截图位于忽略目录 `storage/temporary/`。

白名单回归：控制台后端 27 项通过，含原生白名单阶段的即时拦截/放行、分配置隔离、并发版本冲突、重复/非法输入、热加载失败回滚，以及抖音好友热读、撤销后的实际发送权限检查、自身账号/人数上限和账号切换冲突。真实浏览器验证两类名单增删改、搜索和启停，保存名单保留应用参数草稿；12 个插件接口鉴权通过，手机宽度无溢出且零 JavaScript 错误。验证实例不连接 QQ 或抖音，不实际发送消息。
