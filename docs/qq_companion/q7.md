# Q7 主模型视觉输入

Q7 沿用常驻 `Qwen3.5-9B-Q8_0` 和 `llama-server:8080`。视觉组件随服务启动一次加载；文字、图片、GIF 和视频片段共享同一个请求队列及既有翻唱/训练资源准入。没有独立视觉模型或 8081 服务。

## 固定组件

- llama.cpp：本机 `10099 / 1a064ab09`，使用现有 CUDA 构建。
- 主模型：现有 `Qwen3.5-9B-Q8_0.gguf`，SHA256 `809626574d0cb43d4becfa56169980da2bb448f2299270f7be443cb89d0a6ae4`。
- 投影组件：[unsloth/Qwen3.5-9B-GGUF](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF/tree/3885219b6810b007914f3a7950a8d1b469d598a5)，revision `3885219b6810b007914f3a7950a8d1b469d598a5`，`mmproj-F16.gguf`，918166080 bytes，SHA256 `f70dc3509053962b0d0d3ee8a7eacebf5d60aa560cad78254ae8698516ae029f`，Apache-2.0。
- 对照：[Qwen 模型卡](https://huggingface.co/Qwen/Qwen3.5-9B)、[llama.cpp 多模态说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md)。权重与投影组件分别使用 Q8_0/F16，通过实际推理确认兼容性。

安装器 `scripts/qq_companion/install_q7_vision.py` 支持断点分块下载，完整大小及 SHA256 通过后登记 registry 和 active manifest。注册、激活、启动、Doctor 检查组件；下载或仅启动成功均不会打开视觉能力。

## 输入与预算

`configs/qq_companion/vision.yaml` 是预算入口；所有模型指导语仍在 `configs/qq_companion/prompts.yaml`。普通 QQ 图片直接给原 AstrBot Agent 传入真实 JPEG 像素及原问题，不固定增加一次描述请求。引用消息只接受当前事件已携带的素材链，不读取其他会话的消息。

图片校验后旋转、等比缩至长边 1024；上限 20MB、2000 万像素。GIF 默认按时间选四帧，最多八帧，保留时间及重复帧出现位置。视频上限 180 秒/100MB，CPU FFmpeg 每两秒抽帧，每 24 秒一段、每段最多十二帧；60 秒依次十二、十二、六帧。单次模型请求最多四帧，可因上下文限制继续拆批，保持全部时间戳。抽帧失败区间必须写入 `uncovered_intervals`。

本机构建会将相邻图片合并成 super-frame，导致不同帧内容混在一起；现按图片插入独立标记，API 另将时间戳紧贴对应图片。与上游报告 [llama.cpp #24303](https://github.com/ggml-org/llama.cpp/issues/24303) 一致。真实复测由错误的多色条描述恢复为逐帧红、蓝、绿、黄正方形。

真实后端分词器计算文字；每张图预留 4096 视觉 token，另外扣除 1536 输出及 256 余量。base64 长度不参与视觉 token 计算。服务端 `--parallel 1`，SQLite 统一队列按前台优先、同级先入先出执行；视频每批重新排队。所有 QQ Agent、后台记忆/日记/空间/歌曲通知及可选视觉 API 共用队列，不额外启动 Agent。队列只记录请求身份哈希、阶段、图片数量和状态。

`configs/runtime/qwen3.yaml` 固定视觉 token 下限 1024、上限 4096。主存 prompt cache 收紧至 512MiB：本机 32GB RAM 在后端默认 8192MiB 缓存下曾仅剩约 0.3GiB。最终完整验收期间，系统 RAM 使用峰值约 28.59GiB，结束时约 4.37GiB 可用；GPU 总使用峰值 13322MiB，最低空闲 2656MiB。具体样本见最终报告。

音轨按片段转为 16kHz 单声道，调用现有 SenseVoice；转写时间精度是片段级。无声、ASR 失败均记录，不能声称理解了未转写音频。结构化分析校验对象、动作、OCR、情绪、时间戳、置信度、不确定性；模型置信度不代表校准概率。

## 持久任务与素材

`storage/qq_companion/media_analysis.sqlite3` 保存授权素材、版本化分析和视频任务；文件缓存位于 `media_cache/vision`，默认 24 小时。素材 ID 包含会话身份和内容哈希，跨会话无法读取；QQ 和 API 均不能传入任意本地路径。下载仅允许配置域名，逐次验证重定向、公网 IP、大小及媒体格式。

视频最多尝试三次，重启保留次数、截止时间和片段缓存。只有原 worker 已退出才恢复运行中任务；外发状态不明保持 `uncertain`，避免重发。取消在当前模型请求完成后、下一批开始前生效，并禁止最终外发。后台结果只发送到原始授权会话，保守筛选后存入既有视频知识区，不写用户事实或聊天历史。

群聊关闭或处于静默时段时，后续视频批次和结果外发停止。QQ视频结果使用与普通聊天一致的 `reply/thinking_level/voice` 契约、分句数量及打字节奏；`voice=true` 调用已有TTS并发送真实语音，失败时按普通聊天规则回退分句文字。“（发语音：…）”等动作旁白不能直接外发。分句中途响应不明则保留 `uncertain`，不自动重发已发部分。

AstrBot在插件之前会把图片URL改成本地路径。Q7保留当前事件及已经携带的引用链原始URL，再经过域名、大小与格式校验下载，不读取聊天用户指定的本地路径。素材上传延迟时，可关联同一会话同一发送者最近60秒的问题，配置为 `media_question_window_seconds`；不跨会话借用问题。

抖音仅解析公开分享页已暴露的媒体和元数据，不使用登录 Cookie、不启动浏览器；页面不提供可下载媒体时只报告元数据及失败原因。Q8 浏览器和 Q9 自主分享不随 Q7 开启。

## 可选 API

设置 `QQ_COMPANION_VISION_API=1` 后由现有 supervisor 在 127.0.0.1:8766 启动 `services.vision_api.app`。使用现有 AstrBot Python 3.12 环境，无新增 Transformers 视觉环境。独立 Bearer token 位于本机 `vision_token`，所有业务端点必须认证。

1. `POST /v1/vision/assets`：原始媒体字节，`owner`/`kind` 请求头，返回授权素材 ID。
2. `POST /v1/vision/analyze_image|analyze_sticker|analyze_gif`：JSON `media_id/owner/question`，同步结构化分析。
3. `POST /v1/vision/analyze_video`：相同 JSON，返回任务 ID。
4. `GET /v1/vision/jobs/{id}`：`owner` 请求头查询。
5. `DELETE /v1/vision/jobs/{id}`：相同身份取消未发送任务。

`owner` 由持有本机 token 的受信调用方指定，不能把此接口作为公开多用户身份认证入口。API 仅预处理和调用 8080，不持有模型进程。

## 分能力验收与操作

`vision_gates.json` 分别记录 `image/sticker/gif/video` 的报告。Gate 绑定活动模型、视觉组件、llama.cpp、视觉提示词和预算指纹；这些配置变化后相应旧证据失效，必须重新验收。修改 `vision.yaml` 的 `enabled: false` 可整体停用。

真实模型验收：

```powershell
envs/astrbot/Scripts/python.exe scripts/qq_companion/probe_q7_model.py --output storage/temporary/q7-model-acceptance --fixtures storage/temporary/q7-fixtures --audio-services --enable-passed
```

每类可通过 `--kinds image sticker gif video` 单独选择。`--quick` 仅检查小样本，不得启用。素材为本机原创生成的几何/OCR/表情/动作测试集，20 图片、20 表情、10 GIF、20 视频；报告不代表自然照片或真实场景总体准确率。记录原始结构化结果、实际 token、首内容 token 延迟、队列时间、单实例 PID、显存及 RAM 峰值。识别阈值为测试集目标特征至少 85%，请求失败不得记为通过。图片另外要求换图同问、同图换问、多图比较和三十轮图文交替。

真实 QQ 测试只使用用户授权好友 `1301049831`：

```powershell
runtime_env/python.exe scripts/qq_companion/supervisor.py --q7-acceptance
envs/astrbot/Scripts/python.exe scripts/qq_companion/probe_q7_qq.py --output storage/temporary/q7-live-acceptance
runtime_env/python.exe scripts/qq_companion/supervisor.py --q7-acceptance --stop
```

测试实例使用独立状态，只接收该好友私聊，暂停日记、空间和长期事实采集；原生产数据不会成为测试素材。发送成功只证明 OneBot 接受，不代替好友收回素材后的真实入站/识别/回复证据。最终实际结果见 `acceptance.md`，未通过能力保持关闭。
