## 本次确定的行为

- 常规说说按 Asia/Hong_Kong 自然日每天最多一条，默认 23:40，恰好两句话，总计不超过 100 字。只取当天 Q5 `diary_public_candidates` 视图；不读取私人日记正文。Q5 尚在处理时等到 23:59；当天没有可公开素材则只生成平静心情，不虚构交流。过期不堆积补发。
- 重要事件不设每日次数上限，与常规配额分开。同一事件 ID / 日期只发布一次；元旦、劳动节、国庆节是首批可编辑的公开日历事件。自定义事件由本机管理员添加，不把私人聊天的“重要事实”直接公开。默认当天 10:00 后处理，错过日期不追补。
- 发布内容只对本机配置中的三个好友可见；名单由本次用户指定的两个群成员与当前好友列表交集确认。不会因新进群成员而自动扩充名单。也可配置为仅自己可见。权限必须核对服务端 `ugc_right` 与 `ugc_whitelist`，不只看发布返回成功。
- 好友互动代码已实现：每天 19:30 后一次小范围查看，每位白名单好友最多读取三条、只考虑最新一条；模型在无记忆/历史、无工具的独立请求中决定自然回应，每天最多评论两次、点赞三次，同一说说不重复互动。当前 `interactions_enabled=false` 且能力 Gate 未通过，因此不会实际读取好友说说、评论或点赞。
- 用户本次明确缩小实机测试范围，因此替代旧计划“所有能力全通过才实现”的口径：自身发布和好友互动分别保存能力证据；只启用已通过的能力。`SELF_POST_PASS_INTERACTIONS_PENDING` 不等于完整好友互动兼容通过。

## 修改入口

本机策略：`configs/qq_companion/qzone.local.yaml`（已配置，Git 忽略；参考 `qzone.example.yaml`）。每分钟重读，保存后无需重启；提示词每次请求重读。

| 要调整的行为 | 位置 |
|---|---|
| 每日两句话的口吻、内容取舍 | `configs/qq_companion/prompts.yaml` → `qzone_daily` |
| 重要事件说说的口吻 | 同一文件 → `qzone_event` |
| 是否适合点赞、评论及评论风格 | 同一文件 → `qzone_interaction` |
| 发布时间、等待截止时间、简短程度 | `qzone.local.yaml` → `daily_time`、`daily_deadline`、`daily_max_chars` |
| 可见范围和互动名单 | `visibility`、`friend_allowlist` |
| 重要事件与处理时间 | `events`、`event_time` |
| 好友互动开关、时间和配额 | `interactions_enabled`、`interaction_time`、`comment_daily_limit`、`like_daily_limit` |

提示词负责表达和语义判断；时间、名单、每天一条、事件去重、能力 Gate 和停止开关由代码执行。

本机 CLI（Python 3.12）：

```powershell
envs/astrbot/Scripts/python.exe scripts/qq_companion/qzone.py status
envs/astrbot/Scripts/python.exe scripts/qq_companion/qzone.py configure --time 23:40
envs/astrbot/Scripts/python.exe scripts/qq_companion/qzone.py stop
envs/astrbot/Scripts/python.exe scripts/qq_companion/qzone.py resume
envs/astrbot/Scripts/python.exe scripts/qq_companion/qzone.py configure --disable
envs/astrbot/Scripts/python.exe scripts/qq_companion/qzone.py event --id special-day --date 2026-11-01 --text "管理员确认可公开的纪念事件"
```

`resume` 只解除停止标记，不能绕过能力 Gate。`delete <本地outbox ID>` 只删除本模块登记过且内容/账号一致的自己说说；不接受任意平台 ID。`reconcile` 只核对可能已成功的请求，不重放外发。`test-self --count 5` 是显式管理员测试入口，不会在启动时运行，未验证删除前累计提交预算十条，已验证删除后仍逐条清理。

未来具备好友测试对象时，管理员需实际完成每项五次可见测试，再用 `confirm-interaction-gate --capability read_friend|comment|like --confirmed-visible --evidence "日期、测试次数与网页核验证据"` 记录证据，并单独开启互动策略。该入口只记录管理员的实机证明，不自行开展或伪造测试；此次没有执行。不得仅凭接口成功或本地模拟启用。

## 实现与恢复

`DiaryPublisher` 是唯一调度器，随 AstrBot 插件初始化/卸载；未安装第二个会自主发布的 Qzone 插件。`qzone_client.py` 提供最小 HTTP 执行层，OneBot 仅允许登录信息、Cookie 与身份列表只读动作；Qzone 的读写端点固定、仅 HTTPS，不跟随重定向，不自动重试外发。Cookie 只存内存、只发送给固定 QQ 空间端点，日志只记录安全错误码。

代码、模型和鉴权使用现有 AstrBot Python 3.12、httpx、APScheduler、SQLite、jsonschema 与 Qwen Provider。没有新模型进程；所有生成先持有现有 GPU 准入租约，显式禁用工具、使用独立请求，不调用完整聊天 Agent。

状态独立保存在 `storage/qq_companion/qzone.sqlite3`，不写入 AstrBot 聊天历史、Q5 事实表或日记。SQLite 在外发前原子预约并保存内容哈希、账号、日期、来源、收件对象/可见范围及平台 ID。常规一日配额按账号跨实例生效；删除、失败或结果不确定都不释放已用预约。重要事件不套用日配额。

网络读操作临时失败在下一分钟恢复；Cookie/权限异常立即停止模块，需要本机管理员处理后恢复。外发响应丢失时保留 `unknown`，先凭平台 ID / 内容哈希核对，仅确认、不自动重发。删除前确认是登记过的自己内容，先持久记录 `delete_unknown`，即使返回非 JSON 也随后查询是否确实消失；取消、崩溃后仍可继续核对。无法确认清理结果时停止新增测试。

原版 [Zhalslar Qzone 执行协议](https://github.com/Zhalslar/astrbot_plugin_qzone/blob/main/core/qzone/api.py) 和 [Cookie 会话协议](https://github.com/Zhalslar/astrbot_plugin_qzone/blob/main/core/qzone/session.py) 作为接口参考；本次实时原仓库原始文件/归档下载失败，未将未锁定第三方插件装入生产。执行层由本仓库实现并经当前 SnowLuma 实测，兼容矩阵记录在本地 Gate 表。发布可见参数参考 [qzone_api 的参数记录](https://github.com/huanxin996/qzone_api/blob/main/changes.md)，并以本次服务端实际 `ugc_right/ugc_whitelist` 返回核对。
