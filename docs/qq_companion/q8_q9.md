## 日常行为

Asia/Hong_Kong每天10:00–24:00，无QQ任务时浏览真实推荐流，默认20条/小时；其余时间睡眠，QQ保持正常响应。新视频间隔180秒，滚动一小时限额及检查点持久化，不因聊天暂停或重启补刷。API调频即时生效。

QQ从接受入站任务起，到ASR、Agent/工具、语音合成、模拟打字、分条发送及补发结束持有前台租约。Worker每100毫秒检查，取消后台下载和流式推理、暂停播放器，空闲60秒后恢复。多人任务重叠时全部结束才恢复。GPU翻唱资源门非ready也暂停；不启动第二份模型。

前台占用同时绑定到AstrBot消息管道任务的完成回调。未启动Agent、空回复、下游提前终止、异常或取消，也会释放该事件的占用；正常发送后的重复清理不重置空闲起点，其他并发事件仍保留占用。60秒从最后一个实际消息处理结束开始算，20分钟租约超时仅用于异常兜底，正常退出无需等待它。

视频分析上限保留180秒/100MB：短视频分析整条，超过180秒的普通视频在本地截取前180秒的画面和音轨后分析，不再因时长超限放弃；摘要与兴趣输入明确标注只看了开头，避免推断后续或结局。浏览停留最多180秒，即使后台分析尚未结束也会切到下一条并暂停，等原频率允许后开始下一条。直播按可见播放器结构及无限时长识别，立即跳过，不等待刷视频间隔；预加载或隐藏的播放器不作为当前视频。分析仍复用Q7时间轴和每请求最多4帧、优先级20、共享单并发。主模型流式输出取消后关闭连接，使后端及时释放槽位。Q7视频Gate仍为必要前提，账号登录不代表分析Gate自动通过。

兴趣提示词在`configs/qq_companion/prompts.yaml:douyin_interest`，每次热读，不附示例。符合有趣、好笑、高质量任一即可推荐；分析和兴趣置信度均≥0.70，完整覆盖且无广告、垃圾、明显虚假、敏感或私人信息。公开摘要写入Q5公共视频记忆，带来源链接；按原角色及机器人隔离，不进入私人事实、聊天历史或模型训练。

## 本机API

仅绑定`127.0.0.1:8767`，所有端点要求`Authorization: Bearer <本机douyin_token>`，Token在忽略目录`storage/qq_companion/douyin_token`，不打印到日志。API不注册为QQ Agent工具。

| 方法/路径 | 用途 |
|---|---|
| GET /health | 状态、halt错误码、适配器版本，model_owner始终false |
| GET /v1/douyin/config | 读取配置 |
| PATCH /v1/douyin/config | 严格校验并原子保存开关、好友/退订及策略；未知字段拒绝 |
| GET /v1/douyin/frequency | 当前videos_per_hour |
| PUT /v1/douyin/frequency | JSON `{"videos_per_hour":20}`，严格整数1–120，持久热调 |
| POST /v1/douyin/pause | 禁用并暂停浏览；打断当前后台操作 |
| POST /v1/douyin/resume | 核验后恢复；未核对外发阻止恢复 |
| POST /v1/douyin/retry-failed | 将当前账号可恢复失败加入持久队列，同一修复版本每条只重跑一次，保留分段分析和防重发账本 |
| POST /v1/douyin/browser/open | 打开专用浏览器，仅首次登录需要手工 |
| POST /v1/douyin/browser/verify | 核验账号及已同意好友 |
| GET /v1/douyin/browser/diagnostics | 本机公开页面结构诊断，不导出Cookie/存储 |
| GET /v1/douyin/shares | 查询持久外发记录 |
| POST /v1/douyin/shares/{id}/reconcile | 管理员依据平台记录将uncertain核为sent/failed，需evidence |
| GET /v1/douyin/videos/{id} | 指定视频状态/来源 |
| DELETE /v1/douyin/videos/{id}/memory | 撤销该公开视频记忆，保留审计及防重复状态 |

立即停止分享：PATCH `{"share_enabled":false}`；退订：PATCH完整friends列表，将相应`opted_in`设为false或移除。页面DOM变化、登录失效、验证码、账号受限均halt，不暴力重试。

`douyin-web-visible-v3`按原生推荐元数据区分视频与图文。图文按图片原顺序直接识图，每次最多4张，全部图片分批覆盖；标题作为素材上下文，配乐不下载、不做视频解码或ASR。多图按最多8组逐级合并；图片下载与分析批次均持久缓存，QQ抢占或进程重启后续跑。图文中的timestamp表示图片序号，不表示播放秒数。普通视频继续保留前180秒及音轨，直播立即下一条。

Douyin画面分析输出预算3072 tokens，结果合并4096 tokens；若模型以`finish_reason=length`结束，分别提高至6144、8192 tokens重试一次。每次重试重新进入共享推理队列，保持QQ优先，并重新检查文字、图片和输出预算总和是否超过模型上下文；图像容量不足时沿用Q7分批缩小策略。提示词限制重复描述与条目数量，完整JSON仍需通过原结构校验；重试仍超限则保留失败。每次尝试的预算、阶段、截断正文、finish_reason及usage都写入本机模型日志；QQ聊天的全局1536 token预算不受影响。

重新处理使用`envs/douyin/Scripts/python.exe scripts/qq_companion/douyin.py retry-failed`。当前修复接收`incomplete_douyin_output`、`media_domain_rejected`、旧`video_too_long`及`media_file_too_large`记录；仅作用于当前账号的unavailable记录，不重跑done/filtered/revoked。恢复队列独立于重新观看的频率限额，仍遵守聊天抢占、资源门、工作时段和原分享政策。重启保留队列，已完成的分段缓存继续使用；图文/输出修复与原生小体积版本选择分别登记一次恢复机会，同一修复失败不会无限入队。`/health.recovery`可查看每条记录最新结果，旧尝试仍保留在账本中。

若默认视频整文件超过100 MB下载预算，使用该作品原生元数据中预算内的最高分辨率版本，同分辨率优先较高码率；仍执行域名、重定向、实际下载大小及解码校验，不提高下载上限，也不猜测媒体地址。取得素材后只保留前180秒画面及音轨。找不到预算内原生版本则保留明确失败，不绕过资源限制。
